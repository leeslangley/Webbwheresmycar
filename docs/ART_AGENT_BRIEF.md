# Art agent brief (Opus/Sonnet art directors who BUILD the art themselves)

Context: "Webb, where's my car?" is a Godot 4.7.2 game (iPhone landscape first). Lee's verdict on the first Godot screenshots: "WAAAAYYY off, aim higher, high quality graphics". The structure, logic, UI and tests work; the art is deliberately crude placeholder blocks. YOUR job is to replace the placeholders for ONE area with genuinely beautiful art, by writing the code/shaders/geometry yourself and iterating with your own eyes.

## The look (docs/art/RSAMH_STYLE.md, read it): Rock Star Ate My Hamster (1989) modernised
- One fixed cartoon tableau per place; big expressive caricature characters with heavy outlines; saturated 80s palette; comedy props, posters, parody names; British, affectionate, silly. Mark Webb is a real friend: gentle jokes only, no mocking; no real person's likeness available, caricature only.
- Modern rendering: HD pixel art (art pixel = 2-3 screen px, nearest filtering) with MANY more colours than 1989, material textures (wood grain, wallpaper, paper, enamel, chrome, brick, corrugated iron), real lighting: dark moody ambient (CanvasModulate), warm lamp light vs cold window light (PointLight2D/DirectionalLight2D, LightOccluder2D shadows), TV glow that takes the channel colour, dust motes/steam/smoke (GPUParticles2D), flickering strip lights, subtle film grain/vignette/bloom (post shader godot/art/post.gdshader), parallax on pointer. "Moody and cinematic" is Lee's chosen mood.
- The TV is THE centre of the game: a big chunky 80s CRT (about 760x560 on the 1280x720 stage) in the middle of the office; Mark and Dave seen from behind in chairs in front of it, lit by its glow. All management happens as TV channels (shop, news, adverts, ledger, bookings) on its screen.
- Stage is 1280x720 logical, centred; wide phones show extra strips left/right that only carry background. Touch targets stay >= 64x64.

## Rules of the repo (follow exactly)
- Godot NEVER runs on the Mac (it steals Lee's window focus). Use `sh tools/godot/gtest.sh [test_name]` (headless on CASE; last line GDTEST OK) and `sh tools/godot/gshot.sh <scene.tscn> <out.png> [frames] [WxH]` (renders on CASE under Xvfb with software GL; frames=30+ lets lights/particles settle). View every PNG with the Read tool. Blender is at /opt/homebrew/bin/blender (headless only) if you need to measure or generate textures.
- Work ONLY in your own git worktree (given in your task) on its own branch; commit there with `git add <files>; git commit -m "<message>"` ending with the line `Co-Authored-By: Claude Opus 5.5 <noreply@anthropic.com>`. Never push, tag, merge or touch other worktrees/branches; the planner merges your branch. Never print or read secrets. No network.
- Keep ALL existing tests green (`sh tools/godot/gtest.sh` must end `GDTEST OK`). Scene tests pin node names and root child lists (e.g. godot/tests/test_office_scene.gd, test_garage_scene.gd, test_auction_scene.gd: root children Background, Props, Characters, Lights, Front, Ui, Hotspots, Parallax; hotspot rects). Keep those names/rects/APIs; add NEW tests for any new logic (tests run outside the scene tree: _ready does not fire; call it by hand; no pixel checks in tests).
- GDScript style: tabs, typed signatures, no randf()/randi() in sim code (art may use a seeded RandomNumberGenerator for deterministic textures), no debug print left behind. Player-visible text: ASCII only, pound sign only via CoreFormat.money(), no real brands/people, no he/she/him/her for customers or named people.
- Performance: it must run smoothly on an iPhone with the Mobile renderer (project.godot rendering_method.mobile = "mobile"; CASE screenshots use Compatibility software GL, so keep shaders compatible with both): prefer a few well-made textures/shaders and a handful of lights over hundreds of nodes; generate textures procedurally at build time (Image/NoiseTexture2D/GradientTexture2D) or ship small PNGs under godot/art/ (no huge files).

## Process (this is what makes the result good)
1. Read the style doc and the files you own; take BEFORE screenshots and say what is weak.
2. Build in layers: palette and materials first, then big shapes and silhouettes, then props and details, then lighting and particles, then post. After EVERY layer render and LOOK at the screenshot. Be a harsh art director: compare against the style grammar above and against what a polished indie game would show. Iterate at least 8 render cycles. Fix what looks cheap: flat colours, hard-edged rectangles, labels (no text labels on props!), blown highlights, muddy darks, everything the same brightness, empty areas, misaligned shadows.
3. Final reply (max 25 lines): what you built, the files, the commit hash, test output tail, the final screenshot paths, and an HONEST critique (what is still weak and what you would do next).
