## Decision: fixed height 720, variable width 1280..1568, a 1280x720 STAGE in the middle (your direction, two changes)
- Logical canvas = 720 high, `fullW` wide: 1280 for 16:9 and narrower (iPad 4:3 and desktop letterbox top and bottom exactly as today); otherwise window aspect x 720 rounded UP to a multiple of 4, capped at **1568** (not 1560: iPhone 16 Pro is 874x402 = 1565, Pro Max 956x440 = 1564; 1560 would leave visible black slivers on them). Under 16 px of extra width is ignored (a 1366x768 laptop stays 1280). Rounding up means the canvas overhangs the window by under 2 CSS px a side; only strip art is cropped, never a control.
- STAGE = x 0..1280. Every scene LAYOUT, hit rect, text and test keeps its numbers: `app.w` stays 1280, `app.h` 720, scenes draw in stage coordinates, the app translates by `view.dx`. Strips = stage x < 0 and x > 1280 (up to 144 px each side): background art only, never controls. iPhone 15 Pro (852x393): fullW 1564, 142 px strips = 77 CSS px, bigger than its 59 px notch inset, so the stage clears the notch with no extra work.
- The phone UI does NOT get bigger (scale stays 0.546): the new width is art only. Text-size rules in GU.md are unchanged.
- `app.view` = {fullW, fullH, stageX, stageW, dx (stageX snapped to whole device pixels so sprites stay crisp), left (-stageX), right (1280+stageX), wide, ds, safe:{top,right,bottom,left} stage-relative}. Updated in place on resize and rotation; `app.safe` is the same object as `app.view.safe`.
